# SaaS Template

A BetterBase SaaS boilerplate with **auth**, **payments**, and **multi-tenancy**.

It uses the recommended [IaC-first](../../templates/iac) structure:
schema lives in `betterbase/schema.ts` and all API endpoints are
`betterbase/queries` and `betterbase/mutations` functions that auto-expose
HTTP routes at `/betterbase/:kind/:path/:name`.

## What's included

- **Tenants** — organizations/workspaces (multi-tenancy root).
- **Users** — scoped to a tenant with a role.
- **Subscriptions** — Stripe-style subscription records.
- **Payments** — Stripe-style payment intents (amount in cents, no secrets).
- Tenant-scoped query/mutation examples showing how to use the tenant context.

## Running

```bash
# 1. Scaffold into a new project
mkdir my-app && cd my-app
cp -r <repo>/templates/saas/* .

# (The real `bb init --template saas` is coming; for now copy manually.)

# 2. Configure environment
export DATABASE_URL="postgresql://user:pass@localhost:5432/myapp"
export BETTERBASE_AUTH_SECRET="$(openssl rand -hex 32)"
export STRIPE_SECRET_KEY="sk_live_..."   # for billing integration only

# 3. Install and sync
bb deps install
bb iac sync

# 4. Run
bb dev
```

## Multi-tenancy

Every tenant-scoped table carries a `tenantId` field. Functions take
`tenantId` as an argument and scope queries with `.withIndex("by_tenant", ...)`.

```typescript
// betterbase/queries/tenants.ts
export const listUsers = query({
  args: { tenantId: v.id("tenants") },
  handler: async (ctx, args) => {
    return ctx.db
      .query("users")
      .withIndex("by_tenant", (q) => q.eq("tenantId", args.tenantId))
      .collect();
  },
});
```

## Payments

The `payments` table stores only references and amounts — never the Stripe
secret key. Read `STRIPE_SECRET_KEY` from the environment in your billing
integration (e.g. `src/modules/billing.ts`), in an `action`.
