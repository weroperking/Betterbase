# API Template

A BetterBase **REST API** focused project — no UI. All endpoints are
typed `betterbase/queries` and `betterbase/mutations` functions that
auto-expose HTTP routes at `/betterbase/:kind/:path/:name`.

## What's included

- An `items` table with validated fields (`v.string()`, `v.number()`,
  `v.array(v.string())`, etc.).
- CRUD-style functions: `listItems`, `getItem`, `searchItems`,
  `createItem`, `updateItem`, `deleteItem`.
- A full-text `searchIndex` on `name`.

## Running

```bash
# 1. Scaffold into a new project
mkdir my-api && cd my-api
cp -r <repo>/templates/api/* .

# (The real `bb init --template api` is coming; for now copy manually.)

# 2. Configure environment
export DATABASE_URL="postgresql://user:pass@localhost:5432/myapi"

# 3. Install and sync
bb deps install
bb iac sync

# 4. Run
bb dev
```

## Calling the API

Each function is exposed as an HTTP POST:

```bash
curl -X POST http://localhost:3000/betterbase/mutations/items/createItem \
  -H "Content-Type: application/json" \
  -d '{ "args": { "name": "Widget", "status": "active", "quantity": 10, "tags": ["a","b"] } }'

curl -X POST http://localhost:3000/betterbase/queries/items/listItems \
  -H "Content-Type: application/json" \
  -d '{ "args": {} }'
```

## Notes

- `graphql` is disabled in this template; `autoRest` is enabled.
- Do not edit `betterbase/_generated/*` — regenerated by `bb iac sync`.
